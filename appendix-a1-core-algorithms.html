    Appendix A1: Data-structure and core algorithms (high-level steps)

    Each entry gives what the algorithm solves, its steps in plain words, its cost, and a one-line reason it works. Study sections link here the first time an algorithm appears.

    Binary search

    Solves: find a value in a sorted array, or the first position where a monotone condition becomes true.

    Steps:

    1. keep a low and a high index
    2. look at the middle element
    3. if it is too small discard the left half, otherwise discard the right half
    4. stop when the range is empty.

    Cost: O(log⁡n)O(\log n)O(logn).

    Why it works: each step halves the range that can contain the answer. Common bug: an off-by-one in the loop condition or in computing the middle (use low + (high - low) / 2).

    Merge sort

    Solves: sort nnn items in O(nlog⁡n)O(n \log n)O(nlogn) in the worst case, stably.

    Steps:

    1. split the array into two halves
    2. sort each half recursively
    3. merge the two sorted halves by repeatedly taking the smaller front element.

    Cost: O(nlog⁡n)O(n \log n)O(nlogn) time, OOO(nnn) extra space.

    Why it works: merging two sorted lists takes linear time, and there are log⁡n\log nlogn levels. The same merge step counts inversions (while merging, every time a right-half element is placed before remaining left-half elements, add the number of those left elements).

    Quicksort and randomized quicksort

    Solves: sort in place, fast in practice.

    Steps:

    1. choose a pivot
    2. partition so that smaller elements go left and larger go right
    3. recurse on both sides.

    Cost: expected O(nlog⁡n)O(n \log n)O(nlogn) with a random pivot; worst case O(n2)O(n^{2})O(n2) if pivots are always extreme.

    Why it works: after partition the pivot is in its final place. The worst case can be avoided with a random pivot, median-of-three, or the median-of-medians pivot rule. Three-way partitioning (less than, equal to, greater than) handles many duplicates.

    Heap, heapsort and build-heap

    Solves: a priority queue (insert, extract-min⁡\min min) and sorting. A binary heap is a complete binary tree stored in an array in which each parent is no larger than its children (min⁡\min min-heap). Insert: add at the end and sift up. Extract-min⁡\min min: swap the root with the last element, remove the last, sift down. Build-heap: for each internal node from the last one up to the root, sift it down; total OOO(nnn). Heapsort: build a max⁡\max max-heap, then repeatedly swap the root to the end and sift down; O(nlog⁡n)O(n \log n)O(nlogn), in place, not stable.

    Counting sort and radix sort

    Solves: sort integers from a small range faster than comparison sorting. Counting sort: count how many times each key occurs, turn counts into starting positions (prefix sums), then place each item at its position, scanning from the right to keep it stable. Cost O(n + k) for keys in 0..k-1. Radix sort: sort by the least significant digit first using a stable sort, then the next digit, and so on; O(d (n + k)) for d digits.

    Quickselect and median of medians

    Solves: find the k-th smallest element without sorting. Quickselect steps: pick a random pivot; partition; if the pivot ends at position k you are done; otherwise recurse into only the side that contains position k. Expected O(n). Median of medians makes the worst case O(n): split into groups of 5, take each group's median, recursively find the median of those medians, and use it as the pivot, which guarantees at least 30% of elements on each side.

    Breadth-first search (BFS)

    Solves: shortest paths (fewest edges) from a source in an unweighted graph; connected components; 2-colouring test for bipartiteness.

    Steps: put the source in a queue and mark it visited with distance 0; repeatedly remove the front vertex and, for each unvisited neighbour, mark it visited, set its distance one more, and enqueue it.

    Cost: O(V + E). Bipartite test: colour each new vertex opposite to its parent; an edge between equal colours means an odd cycle, so the graph is not bipartite.

    Depth-first search (DFS)

    Solves: cycle detection, topological order, strongly connected components, connected components.

    Steps: from a vertex, mark it in progress, recurse into each unvisited neighbour, then mark it finished.

    Cost: O(V + E). Edge types in a directed graph: tree, back (to an in-progress ancestor, which means a cycle), forward, cross. A directed graph has a cycle if and only if DFS finds a back edge.

    Topological sort

    Solves: order the vertices of a directed acyclic graph so that every edge goes from earlier to later (scheduling with dependencies). Kahn's method: compute in-degrees; put all vertices with in-degree 0 in a queue; repeatedly remove one, output it, and decrease the in-degree of its neighbours, adding any that reach 0. If fewer than all vertices are output, a cycle exists. DFS method: run DFS and output vertices in reverse finishing order. Cost O(V + E).

    Strongly connected components (Kosaraju)

    Solves: group vertices in a directed graph so that each group's vertices can all reach each other.

    Steps:

    1. run DFS and record finishing times
    2. reverse every edge
    3. run DFS on the reversed graph in decreasing order of finishing time
    4. each DFS tree is one strongly connected component. Cost O(V + E).

    Dijkstra's shortest paths

    Solves: shortest paths from one source in a graph with non-negative edge weights.

    Steps:

    1. set the source distance to 0 and all others to infinity
    2. keep a min⁡\min min-priority queue of vertices by tentative distance
    3. repeatedly extract the closest unfinished vertex u and, for each edge (u, v, w), if dist(u) + w < dist(v), update dist(v) (this is called relaxing the edge).

    Cost: O((V+E)log⁡V)O((V + E) \log V)O((V+E)logV) with a binary heap.

    Why it works: when a vertex is extracted its distance is final, because any other path would pass through an unfinished vertex that is at least as far. Why negative edges break it: a later negative edge could shorten the path to an already finalized vertex.

    Bellman-Ford

    Solves: shortest paths with possibly negative edges, and detects negative cycles reachable from the source.

    Steps:

    1. set distances as in Dijkstra
    2. repeat V - 1 times: relax every edge
    3. do one more pass, and if any distance still improves, a negative cycle exists.

    Cost: O(VE).

    Why it works: after i passes, all shortest paths using at most i edges are correct, and a shortest path has at most V - 1 edges.

    Floyd-Warshall

    Solves: shortest paths between all pairs.

    Steps: let d[i][jjj] be the current best distance; for each intermediate vertex k in turn, for every pair (i, jjj) set d[i][j]=min⁡[j] = \min [j]=min(d[i][jjj], d[i][k] + d[k][jjj]).

    Cost: O(V3)O(V^{3})O(V3). It is dynamic programming over the set of allowed intermediate vertices.

    Minimum spanning tree: Kruskal and Prim

    Solves: connect all vertices with the cheapest set of edges. Kruskal: sort edges by weight; go through them and add an edge if it joins two different components (checked with union-find); stop at V - 1 edges. Prim: start from any vertex; repeatedly add the cheapest edge leaving the current tree, using a priority queue.

    Cost: O(Elog⁡V)O(E \log V)O(ElogV). Why both work (the cut property): the lightest edge crossing any partition of the vertices belongs to some minimum spanning tree.

    Union-find (disjoint sets)

    Solves: keep track of which elements are in the same group while groups merge.

    Steps:

    1. each element points to a parent, roots are group representatives
    2. find follows parents to the root and, along the way, makes every visited node point directly to the root (path compression)
    3. union attaches the root of the smaller-rank tree under the other root (union by rank).

    Cost: almost constant, O(α\alpha α(n)) amortized, where α\alpha α is the inverse Ackermann function.

    Max-flow: Ford-Fulkerson and Edmonds-Karp

    Solves: the largest amount that can be sent from a source to a sink through edges with capacities; also bipartite matching.

    Steps:

    1. start with zero flow
    2. find a path from source to sink in the residual graph (edges with remaining capacity, plus reverse edges for flow already sent)
    3. push the smallest residual capacity along the path
    4. repeat until no path exists. Edmonds-Karp finds each path by BFS and runs in O(VE2)O(V E^{2})O(VE2). Max-flow min⁡\min min-cut theorem: the maximum flow equals the capacity of the smallest cut separating source and sink.

    Dynamic programming: the recipe

    Steps:

    1. define a subproblem with a precise meaning
    2. write a recurrence expressing it through smaller subproblems
    3. fix an evaluation order (or use memoization)
    4. give base cases
    5. say how to read the answer
    6. state time and space. The specific problems below follow the recipe.
    • 01\frac{0}{1}10​ knapsack: f[i][www] is the best value using the first i items with capacity www; f[i][w]=max⁡[w] = \max [w]=max(f[i-1][www], f[i-1][w−wti]+vali[w - wt_{i}] + val_{i}[w−wti​]+vali​). Cost O(nW), pseudo-polynomial because W is a number, not its size in bits.
    • Longest common subsequence: fff[i][jjj] for the prefixes of two strings; if the last characters match, fff[i][j]=f[j] = f[j]=f[i-1][jjj-1] + 1, else max⁡\max max(fff[i-1][jjj], fff[i][jjj-1]). Cost O(mn).
    • Edit distance: f[i][jjj] is the minimum insertions, deletions and substitutions to turn the first i characters of one string into the first jjj of another; f[i][j]=min⁡[j] = \min [j]=min(f[i-1][jjj] + 1, f[i][jjj-1] + 1, f[i-1][jjj-1] + (0 if equal else 1)).
    • Longest increasing subsequence in O(nlog⁡n)O(n \log n)O(nlogn): keep an array tails where tails[k] is the smallest possible last element of an increasing subsequence of length k + 1; for each new element, binary search for its place and overwrite; the length of the array is the answer.
    • Coin change (minimum coins): f[a] = 1+min⁡1 + \min 1+min over coins c of f[a - c], with f[0] = 0.

    Greedy algorithms: interval scheduling and Huffman coding

    Interval scheduling (choose the most non-overlapping intervals): sort by finish time and repeatedly take the earliest-finishing interval compatible with those taken. Proof idea (exchange argument): any optimal solution can swap its first interval for the earliest-finishing one without losing anything. Huffman coding (shortest prefix code for given symbol frequencies): put all symbols in a min⁡\min min-heap by frequency; repeatedly remove the two smallest, join them under a new node whose frequency is their sum, and insert it back; the final tree gives the codes.

    String matching: KMP and Rabin-Karp

    KMP finds a pattern in a text in O(n + m): precompute for each prefix of the pattern the length of its longest proper prefix that is also a suffix (the failure function); scan the text and, on a mismatch, fall back using the failure function instead of restarting. Rabin-Karp: compute a rolling hash of every window of the text with the pattern's length and compare to the pattern's hash, checking characters only on a hash match; expected O(n + m).

    Floyd's cycle detection and linked-list tricks

    To detect a cycle in a linked list, move one pointer one step at a time and another two steps at a time; if they ever meet there is a cycle. To delete a node when you only have a pointer to it (not the head): copy the next node's value into it, then unlink the next node. This does not work for the last node. To reverse a list, walk it once keeping previous, current and next pointers.

    LRU cache design (O(1) get and put)

    Solves: a fixed-size cache that evicts the least recently used item.

    Steps:

    1. keep a hash map from key to a node, and a doubly linked list ordered from most to least recently used
    2. on a get or put, find the node through the map and move it to the front of the list
    3. when the cache is full on a put, remove the node at the tail and delete its key from the map. All operations O(1).

    Miller-Rabin primality test

    Solves: decide whether a large number n is prime.

    Steps:

    1. write n - 1 as 2s2^{s}2s times d with d odd
    2. pick a random base a
    3. compute ada^{d}ad mod n and square repeatedly up to s times, checking for the patterns a prime must follow (a result of 1 or n - 1 at the right place)
    4. if any pattern fails, n is composite. Repeating with kkk random bases makes the chance of a wrong 'prime' answer at most 4−k4^{-k}4−k.
