    Appendix A2: Operating-system, network and database algorithms

    CPU scheduling algorithms

    Solves: decide which ready process runs next on the CPU. Terms: burst time is how long a process needs the CPU; waiting time is time spent in the ready queue; turnaround time is completion time minus arrival time; response time is the time from arrival to first run.

    • First come, first served (FCFS): run in arrival order, no preemption. Simple, but one long job delays everything behind it (the convoy effect).
    • Shortest job first (SJF): run the ready process with the smallest burst. It minimizes average waiting time (exchange argument in section 1.2). The preemptive version, shortest remaining time first (SRTF), preempts when a shorter job arrives. Problem: burst length must be predicted, and long jobs can starve.
    • Round robin (RR): give each process a fixed time quantum in turn; preempted processes go to the back of the queue. Good response time; with a quantum too large it degenerates to FCFS, with a quantum too small the context-switch overhead dominates.
    • Priority scheduling: run the highest-priority process; starvation of low priorities is fixed by aging (raise priority as waiting time grows).
    • Multilevel feedback queue (MLFQ): several queues of decreasing priority; new processes start in the top queue; a process that uses its whole quantum moves down, one that blocks early stays up. It approximates SJF without knowing burst times.

    Worked example: four processes arrive at time 0 with bursts P1=6P_{1} = 6P1​=6, P2=8P_{2} = 8P2​=8, P3=7P_{3} = 7P3​=7, P4=3P_{4} = 3P4​=3. FCFS finishes at 6, 14, 21, 24, so waits are 0, 6, 14, 21 and the average is 10.25. SJF runs P4P_{4}P4​, P1P_{1}P1​, P3P_{3}P3​, P2P_{2}P2​, finishing at 3, 9, 16, 24, so waits are 0, 3, 9, 16 and the average is 7. Round robin with quantum 4 gives completion times P1=17P_{1} = 17P1​=17, P2=21P_{2} = 21P2​=21, P3=24P_{3} = 24P3​=24, P4=15P_{4} = 15P4​=15, so waits (completion minus burst) are 11, 13, 17, 12 and the average is 13.25.

    Page-replacement algorithms

    Solves: when memory is full and a page fault happens, choose which page to evict.

    • FIFO: evict the page that has been in memory longest. Cheap, but can suffer Belady's anomaly (more frames giving more faults).
    • Optimal (OPT): evict the page whose next use is farthest in the future. It needs the future, so it is only a benchmark.
    • Least recently used (LRU): evict the page not used for the longest time. It approximates OPT using the past; needs a timestamp or a stack of pages.
    • Clock (second chance): arrange frames in a circle with a reference bit each; the hand sweeps; if the bit is 1 clear it and move on, if 0 evict that page. It approximates LRU cheaply.

    Worked example: reference string 7,0,1,2,0,3,0,4,2,3,0,3,2 with 3 frames. FIFO has 10 faults, LRU has 9, OPT has 7. Trace LRU: faults on 7, 0, 1; on 2 evict 7; hit on 0; on 3 evict 1; hit on 0; on 4 evict 2; on 2 evict 3; on 3 evict 0; on 0 evict 4; hits on 3 and 2; faults total 9.

    Banker's algorithm (deadlock avoidance)

    Solves: decide whether granting a resource request keeps the system in a safe state, one from which all processes can still finish in some order. Data: Available (free units of each resource), Max (each process's maximum need), Allocation (currently held), and Need = Max - Allocation. Safety check: set Work = Available and mark all processes unfinished; find an unfinished process whose Need is at most Work; pretend it finishes, so add its Allocation to Work and mark it finished; repeat; if all can be finished the state is safe. For a request: check it is at most the process's Need and at most Available; pretend to grant it; run the safety check; if unsafe, undo the grant and make the process wait.

    Mutual exclusion and classic synchronization solutions

    • Peterson's algorithm (two threads, shared memory): each thread sets its flag to true and gives the turn to the other (turn = other); then it waits while the other's flag is true and it is the other's turn; it then enters the critical section and finally clears its own flag. It satisfies mutual exclusion, progress and bounded waiting (on a sequentially consistent machine).
    • Bounded buffer with semaphores: use empty = N (free slots), full = 0 (filled slots) and mutex = 1. Producer: wait(empty); wait(mutex); insert item; signal(mutex); signal(full). Consumer: wait(full); wait(mutex); remove item; signal(mutex); signal(empty). Swapping the order of wait(empty) and wait(mutex) in the producer can deadlock: a producer holding the mutex waits for space that only a consumer (blocked on the mutex) can create.
    • Readers-writers (readers preferred): a readers count protected by a mutex; the first reader locks a write semaphore and the last reader releases it; writers lock the write semaphore for the whole write. Writers can starve.
    • Dining philosophers: five philosophers, five forks; if each grabs the left fork first, all can deadlock. Fixes: let at most four sit at a time; number the forks and always take the lower number first (breaks circular wait); or pick up both forks atomically.

    Disk scheduling: SCAN

    Solves: order the pending disk requests to reduce head movement. FCFS serves in arrival order. SSTF serves the nearest request (can starve far requests). SCAN (the elevator algorithm): move the head in one direction serving requests on the way to the end of the disk, then reverse. C-SCAN: serve in one direction only, then jump back to the start; gives more uniform wait times.

    Routing: link-state and distance-vector

    Link-state (OSPF): every router floods the state of its links to all routers, so all have the full map, then each runs Dijkstra to build its routing table. Distance-vector (RIP): each router keeps a table of distances to all destinations and periodically sends it to neighbours; on receiving a neighbour's table, it updates d(x)=min⁡d(x) = \min d(x)=min over neighbours v of [cost(xxx, v) + dvd_{v}dv​(destination)] (this is distributed Bellman-Ford). Count-to-infinity is the problem where bad news (a link failure) spreads slowly; fixes include split horizon and poison reverse.

    TCP congestion control

    Solves: send as fast as the network allows without overloading it. State: congestion window cwnd (segments in flight allowed) and slow-start threshold ssthresh. Slow start: start with cwnd = 1 segment and double it every round trip (add one per acknowledgement) until cwnd reaches ssthresh. Congestion avoidance: then add one segment per round trip (additive increase). On three duplicate acknowledgements (mild loss): set ssthresh = cwnd / 2 and cwnd = ssthresh (multiplicative decrease, fast recovery). On a timeout (severe loss): set ssthresh = cwnd / 2, cwnd = 1, and go back to slow start. This additive-increase multiplicative-decrease (AIMD) rule converges to a fair share between competing flows.

    Ethernet CSMA/CD and exponential backoff

    Solves: sharing one wire between many senders.

    Steps:

    1. listen
    2. if the line is idle, send while listening
    3. if a collision is detected, stop, send a jam signal, and wait a random number of slot times chosen uniformly from 0 to 2n−12^{n} - 12n−1 after the n-th collision (n capped at 10), then retry
    4. give up after 16 attempts. Wireless uses CSMA/CA (collision avoidance) because a sender cannot hear collisions while sending.

    Two-phase locking and the serializability test

    Solves: allow concurrent transactions while ensuring the result equals some serial order. Two-phase locking (2PL): a transaction acquires locks in a growing phase and, once it releases any lock, never acquires another (shrinking phase). It guarantees conflict-serializability. Strict 2PL holds exclusive locks until commit or abort, which prevents cascading aborts. Test of a given schedule: build a precedence graph with a node per transaction and an edge Ti to Tj whenever an operation of Ti conflicts (same item, at least one write) with a later operation of Tj; the schedule is conflict-serializable if and only if the graph has no cycle.

    B+ tree search and insert

    Solves: store sorted keys on disk so that search, insert and range queries touch few pages. Structure: internal nodes hold keys that guide the search to a child; all data pointers live in the leaves, which are linked left to right. Search: from the root, at each node follow the child whose key range contains the target; end at a leaf. Insert: find the leaf and insert; if the leaf overflows, split it in two and copy the middle key up into the parent; if the parent overflows, split it and push the middle key up; this can propagate to the root, which then grows the tree by one level.

    Cost: height about log⁡\log log base f of n, where f is the fan-out. A range query finds the first key and then follows leaf links.

    Attribute closure and BCNF decomposition

    Attribute closure of a set X under functional dependencies (FDs): start with X; repeatedly, for any FD A to B with A inside the current set, add B; stop when nothing changes. X is a superkey if its closure is all attributes. BCNF decomposition: while some FD X to Y in a table R has X not a superkey, split R into (X union Y) and (R minus (Y minus X)); repeat on the pieces. The result is lossless, but may lose some dependencies.
