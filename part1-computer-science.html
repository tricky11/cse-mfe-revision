    1.1 Algorithms and data structures

    Concept primer

    This section tests whether you can pick the right data structure, state the cost of an operation, and argue that an algorithm is correct. Memorized solutions matter less than method: start from a small example, state the brute-force answer, and improve it.

    Cost model. We count basic steps as a function of the input size nnn. O(fff(nnn)) means "at most a constant times fff(nnn) for large nnn" (an upper bound), Ω(f(n))\Omega (f(n))Ω(f(n)) is a lower bound, and Θ(f(n))\Theta (f(n))Θ(f(n)) means both. Typical growth, from cheap to expensive: log⁡n\log nlogn, nnn, nlog⁡nn \log nnlogn, n2n^{2}n2, n3n^{3}n3, 2n2^{n}2n. A cost of nlog⁡nn \log nnlogn sorts a million items in about 20 million steps; n2n^{2}n2 needs a trillion. Amortized cost averages over a sequence of operations: appending to a dynamic array costs O(1) on average even though an occasional append copies the whole array, because doubling the capacity spreads the copying cost over many appends.

    Recurrences and the Master theorem. Divide-and-conquer algorithms split a problem of size nnn into a subproblems of size nb\frac{n}{b}bn​ and spend fff(nnn) combining: T(n)=aT(nb)+f(n)T(n) = a T(\frac{n}{b}) + f(n)T(n)=aT(bn​)+f(n). Compare nnn^(log⁡b\log _{b}logb​ a) (the total work at the leaves) with fff(nnn). If the leaves dominate, T(n)=ΘT(n) = \Theta T(n)=Θ(nnn^(log⁡b\log _{b}logb​ a)); if both are equal, you pick up an extra log⁡\log log factor, T(n)=Θ(f(n)log⁡n)T(n) = \Theta (f(n) \log n)T(n)=Θ(f(n)logn); if the combine step dominates (and is regular), T(n)=Θ(f(n))T(n) = \Theta (f(n))T(n)=Θ(f(n)). Merge sort has a=2a = 2a=2, b=2b = 2b=2, f(n)=nf(n) = nf(n)=n, so both are nnn and T(n)=Θ(nlog⁡n)T(n) = \Theta (n \log n)T(n)=Θ(nlogn).

    Choosing structures. An array gives OOO(1) indexing but OOO(nnn) insertion in the middle. A linked list gives OOO(1) insertion once you hold the position but OOO(nnn) search. A hash table gives OOO(1) expected lookup but no ordering. A balanced binary search tree gives O(log⁡n)O(\log n)O(logn) for search, insert, delete and ordered queries (predecessor, range). A heap gives OOO(1) minimum and O(log⁡n)O(\log n)O(logn) insert and delete-min⁡\min min, which is exactly what a priority queue needs. A stack and a queue are access disciplines (last in first out, first in first out).

    Graphs. A graph is vertices V joined by edges E. Store it as adjacency lists (cost O(V + E) space) unless it is dense. Breadth-first search finds shortest paths in unweighted graphs; depth-first search finds structure (cycles, topological order, components); Dijkstra handles non-negative weights; Bellman-Ford handles negative weights and detects negative cycles; minimum spanning trees connect everything at least total weight.

    Proof habits that impress. For loops, state an invariant (a fact true before every iteration) and show it gives the answer at the end. For greedy algorithms, use an exchange argument: take any optimal solution and show you can swap in the greedy choice without making it worse. For dynamic programming, define the subproblem in one sentence, write the recurrence, say the order of evaluation, and give the base cases.

    Common pitfalls. Forgetting that a hash table's worst case is O(n); ignoring recursion depth (stack space); off-by-one errors in binary search; assuming sorted input; not asking whether values can be negative, duplicated or empty.

    How to answer any algorithm question. (1) Restate the problem and ask about input size and edge cases. (2) Give a simple brute-force idea and its cost. (3) Improve it, saying which observation helps. (4) State time and space. (5) Test on a small example and on edge cases (empty, one element, duplicates, sorted input). Algorithms named below link to their step-by-step description in Appendix A.

    Q1. What is the time complexity of quicksort? Can the worst case be made O(nlog⁡n)O(n \log n)O(nlogn)?

    Answer. Average O(nlog⁡n)O(n \log n)O(nlogn) and worst case O(n2)O(n^{2})O(n2). Quicksort picks a pivot, puts smaller elements on its left and larger on its right, and sorts each side. The worst case happens when the pivot is always the smallest or largest element (for example, always taking the first element of an already sorted array), so one side has nnn - 1 elements and the recurrence is T(n)=T(n−1)+nT(n) = T(n - 1) + nT(n)=T(n−1)+n, which is O(n2)O(n^{2})O(n2). To get a guaranteed O(nlog⁡n)O(n \log n)O(nlogn) you need a pivot that splits the array in a fixed proportion: the median-of-medians rule (see Quickselect and median of medians) finds such a pivot in linear time. In practice a random pivot makes the bad case extremely unlikely, with expected cost about 1.39nlog⁡2n1.39 n \log_2 n1.39nlog2​n comparisons. The base of the logarithm does not matter for big-OOO because changing base multiplies by a constant.

    Q2. What is the best possible time for sorting? Prove it.

    Answer. For sorting by comparisons, Ω(nlog⁡n)\Omega (n \log n)Ω(nlogn). Proof: a comparison sort can be drawn as a binary decision tree where each internal node is one comparison and each leaf is one output order. The sorted result can be any of the nnn! orderings of the input, so the tree needs at least nnn! leaves. A binary tree of height hhh has at most 2h2^{h}2h leaves, so 2h≥n2^{h} \ge n2h≥n!, hence h≥log⁡2h \ge \log_2 h≥log2​(nnn!). Since nnn! >= (n2)n2(\frac{n}{2})^{\frac{n}{2}}(2n​)2n​, log⁡2\log_2 log2​(nnn!) >= (n2)log⁡2(n2)(\frac{n}{2}) \log_2 (\frac{n}{2})(2n​)log2​(2n​), which is Ω(nlog⁡n)\Omega (n \log n)Ω(nlogn). Linear-time sorts such as counting sort and radix sort do not compare items; they use the fact that keys are integers in a limited range, so they are only usable for such keys (or fixed-length strings). Be ready to write this proof in under five minutes.

    Q3. Can you 'sort a graph'?

    Answer. This asks about ordering the vertices of a directed graph so that every edge goes from an earlier vertex to a later one, as when tasks have prerequisites. That is a topological sort, possible if and only if the graph has no directed cycle. Give both methods: Kahn's (repeatedly remove a vertex with no incoming edges) and DFS (output vertices in reverse finishing order). Both run in O(V + E). Note that a general graph has no natural linear order, and that a topological order is the right notion when edges mean 'must come before'.

    Q4. Give an example of a min⁡\min min-heap. How do you convert it into a max⁡\max max-heap, and what is the cost?

    Answer. A min-heap is a complete binary tree stored in an array in which each parent is at most its children, for example [1, 3, 2, 7, 4, 5, 6]. To turn it into a max⁡\max max-heap, ignore the existing order and run build-heap with the reversed comparison: for each internal node from the last one up to the root, sift it down so that it is at least as large as its children. This takes OOO(nnn), not O(nlog⁡n)O(n \log n)O(nlogn): a node at height h costs OOO(h) to sift, there are at most n2h+1\frac{n}{2^{h+1}}2h+1n​ nodes of that height, and the sum of h2h\frac{h}{2^{h}}2hh​ is 2.

    Q6. How do you detect a cycle in a directed graph?

    Answer. Two ways, each O(V + E). (a) DFS with three states per vertex: unvisited, in progress (on the current recursion path), finished. If the search reaches a vertex that is in progress, it has found an edge back to an ancestor, and that is a cycle. (b) Kahn's topological sort: if after removing zero-in-degree vertices repeatedly some vertices remain, they lie on or after a cycle. For an undirected graph, use union-find or DFS ignoring the parent edge.

    Q7. You are given a pointer to a node in a singly linked list, not the head. Delete that node.

    Answer. Copy the value of the next node into this node, then make this node's next pointer skip the next node (and free it). This works in O(1) for any node except the last; for the last node it cannot be done without the head, so state that limitation. See linked-list tricks.

    Q9. Count the inversions in an array. (An inversion is a pair of positions i<ji < ji<j with a[iii] > a[jjj]; it measures how far the array is from sorted.)

    Answer. Brute force checks all pairs in O(n2)O(n^{2})O(n2). Better: run merge sort. While merging two sorted halves, whenever you take an element from the right half before the remaining left-half elements, those remaining left elements are all larger and each forms an inversion with it, so add their count. Total O(nlog⁡n)O(n \log n)O(nlogn).

    Example: [2, 4, 1, 3, 5] has inversions (2,1), (4,1), (4,3), so 3.

    Q10. Given an array and a target T, find two numbers that sum to T.

    Answer. Brute force O(n2)O(n^{2})O(n2). Better: scan once, keeping a hash set of values seen; for each x check whether T - x is in the set; OOO(nnn) time, OOO(nnn) space. If the array is sorted, use two pointers from both ends (move the left pointer right if the sum is too small, the right pointer left if too large): OOO(nnn) time and OOO(1) space.

    Q11. Find the k-th smallest element of an unsorted array.

    Answer. Sorting gives O(nlog⁡n)O(n \log n)O(nlogn). Quickselect (steps here) gives expected OOO(nnn): partition around a random pivot, and recurse only into the side that holds position kkk. A heap of size kkk gives O(nlog⁡k)O(n \log k)O(nlogk), useful for streams.

    Q12. Show with a concrete example why Dijkstra's algorithm fails with a negative edge.

    Answer. Take edges A to B of weight 2, A to C of weight 5, and C to B of weight -4. The true shortest distance from A to B is 5−4=15 - 4 = 15−4=1 (through C). Dijkstra extracts B first at distance 2 and declares it final, never revisiting it, so it reports 2. Its correctness proof assumes any other path to a vertex is at least as long once the vertex is extracted, which fails when a later edge can reduce the length. Bellman-Ford relaxes every edge V - 1 times, so it finds distance 1 and can also detect a negative cycle.

    Q13. Kruskal and Prim both give a minimum spanning tree. Why does the greedy choice work?

    Answer. Cut property: for any split of the vertices into two groups, the lightest edge between the groups belongs to some minimum spanning tree. Proof: if a tree T did not contain that edge e, adding e to T creates a cycle, which must cross the cut again at another edge f that is no lighter than e; swapping f for e gives a tree no heavier. Both Kruskal and Prim always add an edge that is the lightest across some cut, so they stay inside an optimal tree. Kruskal needs union-find to check that an edge joins two different components.

    Q14. The 01\frac{0}{1}10​ knapsack problem has an O(nW) algorithm, yet it is NP-hard. Is that a contradiction?

    The problem: n items have weights and values; choose items with total weight at most W to maximize total value, each item used at most once.

    Answer. No. The dynamic program has a table of n rows and WWW columns, so its running time is polynomial in the number WWW, but the input only needs about log⁡W\log WlogW bits to write WWW down; time polynomial in the numeric value rather than in the input length is called pseudo-polynomial. If WWW is exponentially large in the number of bits, the table is exponentially large. So there is no contradiction, and no polynomial algorithm in the input length is known.

    Q15. Compute the edit distance between 'kitten' and 'sitting', and explain the method.

    The problem: the edit distance is the smallest number of single-character insertions, deletions and substitutions needed to turn one word into another.

    Answer. Use the edit-distance dynamic program: f[iii][jjj] is the distance between the first iii letters of one word and the first jjj of the other, f[iii][0]=i[0] = i[0]=i and f[0][j]=j[j] = j[j]=j, and f[iii][j]=min⁡[j] = \min [j]=min(f[iii-1][jjj] + 1, f[iii][jjj-1] + 1, f[iii-1][jjj-1] + (0 if the letters match, else 1)). For these words the answer is 3: substitute k with s, substitute e with iii, and insert g at the end. Cost O(mn) time.

    Q16. Find the length of the longest common subsequence of ABCBDAB and BDCABA.

    The problem: a subsequence keeps letters in order but may skip letters; find the longest one that appears in both strings.

    Answer. Use the LCS dynamic program: fff[i][j]=f[j] = f[j]=f[i-1][jjj-1] + 1 if the i-th and jjj-th letters match, otherwise max⁡\max max(fff[i-1][jjj], fff[i][jjj-1]). The answer here is 4, for example BCBA. Cost O(mn); to recover the subsequence itself, walk back through the table from the bottom-right corner.

    Q17. Why is appending to a dynamic array O(1) amortized, even though resizing costs O(n)?

    The problem: an array that doubles its capacity when full; a single append occasionally copies everything.

    Answer. Over n appends, the copies happen at sizes 1, 2, 4, ..., up to less than n, and their total is less than 2n. Adding the n writes gives fewer than 3n operations, so the average cost per append is at most 3, a constant. (Aggregate method of amortized analysis. The accounting method says: charge 3 per append, 1 for the write and 2 saved to pay for copying that item and one older item at the next resize.)

    Q18. How does a hash table work, and what is its expected cost?

    Answer. A hash function maps a key to one of m buckets. With chaining, each bucket holds a list of keys that hash there. With a good hash function and load factor α=nm\alpha = \frac{n}{m}α=mn​, an unsuccessful search examines about α\alpha α items, so the expected cost is O(1+α)O(1 + \alpha )O(1+α). Keep α\alpha α below a constant by doubling m and rehashing when the table gets full, which is amortized OOO(1) per insert. Open addressing stores keys in the table itself and probes alternative slots on collision; it needs α<1\alpha < 1α<1 and handles deletions with markers. Universal hashing picks the hash function at random from a family so that no fixed input can be bad for it.

    Q19. Design a data structure with insert, delete and get-random-element, all in O(1) average time.

    Answer. Keep the elements in an array and a hash map from element to its index in the array. Insert: append to the array and record the index. Get-random: pick a random index in the array. Delete: look up the element's index, copy the last array element into that position, update the last element's index in the map, then remove the last array slot and the deleted key from the map.

    Q20. Support adding numbers one at a time and querying the median at any time.

    Answer. Keep a max⁡\max max-heap for the smaller half and a min⁡\min min-heap for the larger half, with sizes differing by at most one. Insert a number into the correct heap, then move the top of one heap to the other if the sizes become unbalanced. The median is the top of the larger heap, or the average of both tops if equal sizes. Insert O(log⁡n)O(\log n)O(logn), median OOO(1). See heaps.

    Q21. Merge k sorted lists with N elements in total.

    Answer. Put the first element of each list into a min⁡\min min-heap along with which list it came from. Repeatedly remove the smallest, append it to the output, and insert the next element from the same list. Each element enters and leaves the heap once, and the heap has at most kkk items, so the total cost is O(Nlog⁡k)O(N \log k)O(Nlogk).

    Q22. Find the contiguous subarray with the largest sum (maximum subarray).

    Answer. Kadane's method, one pass: keep best_here, the best sum of a subarray ending at the current element, as max⁡\max max(x, best_here + x), and keep the overall maximum. For [-2, 1, -3, 4, -1, 2, 1, -5, 4] the answer is 6 (the subarray 4, -1, 2, 1). O(n) time, O(1) space.

    Q23. Search for a value in a sorted array that has been rotated, for example [4, 5, 6, 7, 0, 1, 2].

    Answer. Use binary search with one extra step: at the middle, at least one half is sorted (compare the middle value to the end values). If the target lies inside the sorted half's range, search there; otherwise search the other half. O(log⁡n)O(\log n)O(logn).

    Q24. Find a cycle in a linked list, and the node where the cycle starts.

    Answer. Floyd's method (see linked-list tricks): a slow pointer moves one step and a fast pointer moves two; if they meet there is a cycle. To find the start, reset one pointer to the head and move both one step at a time; they meet at the cycle's start. O(n) time, O(1) space.

    Q25. Check whether one string is a substring of another; find the smallest circle enclosing a set of points.

    Answer. Substring: the naive method is O(nm); KMP is O(n + m) using a table of how far to fall back after a mismatch; Rabin-Karp uses a rolling hash. Smallest enclosing circle: a randomized incremental algorithm (Welzl) runs in expected O(n): add points in random order, and when a new point lies outside the current circle, the new circle must pass through that point, so recompute with that point fixed.

    Q26. What are P, NP, NP-complete, and how would you prove a new problem is NP-hard?

    Answer. P is the set of decision problems solvable in time polynomial in the input size. NP is the set whose 'yes' answers can be checked in polynomial time given a certificate (for example, a colouring of a graph can be checked quickly). A problem is NP-hard if every problem in NP reduces to it in polynomial time, and NP-complete if it is also in NP. To prove a new problem X NP-hard, reduce a known NP-hard problem Y to X: show how to turn any instance of Y into an instance of X in polynomial time such that the answers agree.

    Example: Vertex Cover (is there a set of at most k vertices touching every edge?) is NP-hard by reduction from Independent Set (is there a set of at least k vertices with no edge among them?), because a set S is independent exactly when the remaining vertices form a vertex cover; so G has an independent set of size k exactly when it has a vertex cover of size n - k.

    Q27. What is the time complexity of computing the n-th Fibonacci number by the recursive definition, by dynamic programming, and by fast methods?

    Answer. Plain recursion recomputes the same values and takes exponential time, about 1.618n1.618^{n}1.618n calls. Memoization or a loop is OOO(nnn). Using the 2 by 2 matrix [[1,1],[1,0]] raised to the nnn-th power by repeated squaring takes O(log⁡n)O(\log n)O(logn) arithmetic operations (the numbers themselves grow, so bit complexity is larger).

    1.2 Operating systems

    Concept primer

    Operating systems questions check that you understand what the OS hides from programs: the CPU (processes and scheduling), memory (virtual memory and paging), and shared state (synchronization). Always answer with the problem the mechanism solves.

    Processes and threads. A process is a running program with its own address space (code, heap, stack, open files). A thread is a unit of execution inside a process; threads of one process share memory, so they communicate cheaply but must synchronize. A context switch saves one thread's registers and restores another's; it costs microseconds and also disturbs the cache. System calls (read, write, fork) are controlled entry points into the kernel; the mode switch from user to kernel mode is done by a trap instruction.

    Scheduling. The scheduler picks the next ready process. Metrics: turnaround time (finish minus arrival), waiting time (time spent ready but not running), response time (time to first run), throughput. First-come first-served is simple but suffers the convoy effect (short jobs stuck behind a long one). Shortest-job-first minimizes average waiting time but needs to know run times and can starve long jobs. Round robin gives each process a time slice (quantum) and cycles; a very small quantum wastes time in switches, a very large one degenerates to first-come first-served. Priority scheduling needs aging to avoid starvation.

    Synchronization. A race condition arises when the result depends on the interleaving of unsynchronized accesses to shared data. A critical section is code that touches shared data; mutual exclusion lets one thread in at a time. Locks, semaphores (a counter with wait and signal) and monitors (a lock plus condition variables) are the tools. Deadlock needs four conditions at once: mutual exclusion, hold and wait, no preemption, circular wait; break any one to prevent it (for example, always acquire locks in a fixed order).

    Virtual memory. Each process sees its own contiguous address space. The hardware splits an address into a page number and an offset; a page table maps page numbers to physical frames. The translation lookaside buffer (TLB) caches recent translations. If a page is not in memory, a page fault brings it from disk. Because a fault costs milliseconds while memory access costs nanoseconds, even a tiny fault rate matters: effective access time = (1 - p) x memory time + p x fault time. Page replacement (FIFO, LRU, optimal) chooses the victim; thrashing happens when the working set does not fit and the system spends its time paging.

    Files and IO\frac{I}{O}OI​. A file system maps names to blocks on disk (inodes hold metadata and block pointers). Disk scheduling reorders requests to cut seek time. Know the difference between blocking, non-blocking and asynchronous IO\frac{I}{O}OI​.

    Systems topics reward understanding mechanisms. Know the ideas and be able to do the numerical problems by hand.

    Q1. What is the difference between a process and a thread?

    Answer. A process is a running program with its own address space (code, data, heap, stack), open files and a process control block (PCB) the OS keeps. A thread is a unit of execution inside a process: threads of one process share the code, heap, global data and open files, but each has its own stack, registers and program counter. Consequences: creating and switching threads is cheaper than for processes (no change of address space), communication between threads is easy through shared memory, but a bug in one thread can corrupt the whole process, and shared data needs synchronization. Processes are isolated from each other, so one crash does not take down another.

    Q2. How is CPU time shared between processes? Which scheduling algorithms do you know and how do they differ?

    Answer. The scheduler picks which ready process runs next, and the dispatcher switches to it. Algorithms: first come first served, shortest job first, shortest remaining time first, round robin, priority, and multilevel feedback queue, each described with its trade-off in CPU scheduling algorithms, which also has a worked four-process example (average waiting times 10.25 for FCFS, 7 for SJF and 13.25 for round robin with quantum 4). One-line guidance: use round robin or multilevel feedback for interactive systems (good response time), SJF-like policies when jobs lengths are known and throughput matters, priority with aging when some work is more urgent, and earliest-deadline-first or rate-monotonic for hard real-time tasks.

    Q3. Is shortest job first optimal? Prove it.

    Answer. Optimal for average waiting time among all non-preemptive schedules when all jobs are available at time 0. Proof by exchange. Run jobs one after another. The burst time of the job in position i adds to the waiting time of every job after it, which is n - i jobs, so total waiting time is the sum over positions of (n - i) times that position's burst. Suppose two adjacent jobs j then k have tj>tkt_{j} > t_{k}tj​>tk​. Swap them. Only the waiting times of these two change: before, k waited for j (an extra tjt_{j}tj​); after, j waits for k (an extra tkt_{k}tk​). All jobs before the pair and all jobs after it see the same start time as before. So the total changes by tk−tjt_{k} - t_{j}tk​−tj​, which is negative. Any order that has a longer job directly before a shorter one can therefore be improved, so the best order has bursts in non-decreasing order, which is SJF. Caveats to mention: burst lengths are not known in advance (estimate with an exponential average of past bursts), and long jobs may starve.

    Q4. Describe the states of a process and the transitions between them.

    Answer. New (being created), ready (waiting for the CPU), running (on the CPU), waiting or blocked (waiting for IO\frac{I}{O}OI​ or an event), terminated. Transitions: new to ready when admitted; ready to running when the scheduler dispatches it; running to ready when its time slice ends or a higher-priority process arrives (preemption); running to waiting when it requests IO\frac{I}{O}OI​ or waits on a lock; waiting to ready when the IO\frac{I}{O}OI​ finishes; running to terminated when it exits. A process cannot go directly from waiting to running; it must pass through ready.

    Q5. How are processes loaded into memory and removed after they finish?

    Answer. To start a program, the OS creates a process (on Unix: fork makes a copy, exec replaces it with the new program), the loader reads the executable and sets up the address space (code, data, heap, stack) using virtual memory: pages are mapped but usually not loaded until first touched (demand paging). The kernel keeps a page table for the process and a PCB. When the process finishes or is killed, the OS closes its files, frees its frames and page tables, removes its PCB (after the parent has read its exit status; until then it is a zombie), and re-parents any children (orphans) to init.

    Q6. What happens during a context switch and why is it costly?

    Answer. The OS saves the running process's registers and program counter in its PCB, picks another process, loads its saved state, and switches address space (page table pointer). Costs: the direct work of saving and restoring state, flushing or invalidating the TLB when the address space changes, and indirect cost from losing the CPU caches' contents (the new process starts with a cold cache). Thread switches within a process avoid the address-space change.

    Q7. Define a race condition and the three requirements for a critical-section solution. Give a solution to the bounded-buffer (producer-consumer) problem.

    The problem: two threads share a buffer of N slots; producers add items, consumers remove them; the program must not overwrite full slots or read empty ones, and must not corrupt the buffer when both run at once.

    Answer. A race condition is when the result depends on the unlucky interleaving of unsynchronized accesses to shared data (for example, two threads each doing counter = counter + 1 can lose an update). A correct critical-section solution needs mutual exclusion (at most one thread inside), progress (if no one is inside, a waiting thread can enter without being blocked by threads outside), and bounded waiting (no thread waits forever). The semaphore solution with counters empty, full and a mutex is written out in mutual exclusion and classic synchronization solutions, including why swapping the order of the two waits in the producer deadlocks.

    Q8. What are the four conditions for deadlock? Give an example and show how to prevent it.

    Answer. All four must hold: mutual exclusion (resources cannot be shared), hold and wait (a process holds one resource while waiting for another), no preemption (resources cannot be taken away), circular wait (a cycle of processes each waiting for a resource held by the next).

    Example: thread A locks X then wants Y; thread B locks Y then wants X; each waits forever. Prevention by breaking one condition; the most practical is to break circular wait by ordering resources and always locking in increasing order (so both threads lock X before Y). Other options: request all resources at once (breaks hold and wait), allow preemption, or use avoidance with the banker's algorithm.

    Q10. A system has 32-bit virtual addresses and 4 KB pages. How is an address split, and how big is a single-level page table with 4-byte entries?

    Answer. 4 KB = 2122^{12}212 bytes, so the low 12 bits are the offset within the page, and the high 20 bits are the page number.     Q12. What exactly happens on a page fault?

    Answer. (1) The CPU traps to the OS because the page table entry says the page is not in memory. (2) The OS checks that the address is valid for this process (otherwise a segmentation fault). (3) It finds a free frame; if none, it chooses a victim with a replacement policy and, if the victim is dirty, writes it to disk. (4) It starts a disk read of the needed page into the frame and runs another process meanwhile. (5) When the read completes, it updates the page table and TLB. (6) It restarts the instruction that faulted. Cost is millions of CPU cycles, so even a tiny fault rate hurts: with memory time 100 ns, fault service time 8 ms and fault rate ppp, effective time is about 100 + 8,000,000 ppp ns, so p=0.0001p = 0.0001p=0.0001 already makes memory access about nine times slower (900 ns).

    Q13. Compare FIFO, LRU and OPT page replacement on a string, and show Belady's anomaly.

    Answer. For the string 7,0,1,2,0,3,0,4,2,3,0,3,2 with 3 frames: FIFO 10 faults, LRU 9, OPT 7 (full trace in page-replacement algorithms). Belady's anomaly: for the string 1,2,3,4,1,2,5,1,2,3,4,5, FIFO has 9 faults with 3 frames but 10 faults with 4 frames, so adding memory made it worse. LRU and OPT never do this because they are stack algorithms: the set of pages kept with k frames is always contained in the set kept with k + 1 frames.

    Q14. What is thrashing and how do you stop it?

    Answer. Thrashing is when the system spends most of its time swapping pages in and out rather than running, because the combined working sets of the running processes do not fit in memory; CPU utilization falls, and a naive scheduler then admits more processes, making it worse. Fixes: the working-set model (give each process enough frames for the pages it has used in a recent window, and suspend processes that cannot be given that), page-fault-frequency control (add frames if a process faults too often, take them away if too rarely), and limiting the degree of multiprogramming.

    Q15. What are copy-on-write and memory-mapped files, and why do they matter?

    Answer. Copy-on-write: after fork the child shares the parent's pages marked read-only; only when either writes a page does the OS copy it. This makes fork cheap, especially when the child calls exec straight away. Memory-mapped files map a file into the address space so that reads and writes become ordinary memory access, with the OS paging the file in and out; useful for large files and shared memory between processes.

    Q16. Explain what an inode is and how a file is read; what does journaling do?

    Answer. An inode stores a file's metadata (size, owner, permissions, timestamps) and pointers to its data blocks (direct pointers, then single, double and triple indirect blocks for larger files); a directory maps names to inode numbers. To read a file: follow the path through directories to find its inode, then read the data blocks the inode points to, through the buffer cache. Journaling writes a record of intended metadata changes to a log⁡\log log before applying them, so after a crash the system replays or discards the log⁡\log log instead of scanning the whole disk, keeping the file system consistent.

    Q17. What is the difference between a mutex, a semaphore and a spinlock? When would you use each?

    Answer. A mutex is a lock owned by the thread that locked it; others sleep until it is released; use it to protect a critical section. A counting semaphore holds a number of permits, wait() takes one (sleeping if none), signal() releases one, and any thread may signal; use it to count resources or to signal between threads. A spinlock makes a waiting thread loop (busy-wait) instead of sleeping; it is better only when the lock will be held for a very short time (shorter than a context switch), as in kernel code on multiprocessors.

    Q18. What are the differences between an interrupt, a trap and a system call?

    Answer. An interrupt is an asynchronous signal from hardware (a timer or a device finishing IO\frac{I}{O}OI​) that makes the CPU run an interrupt handler. A trap (exception) is synchronous, caused by the running instruction (divide by zero, page fault). A system call is a deliberate trap by a program to ask the kernel for a service (read, write, fork); it switches from user mode to kernel mode. Kernel mode can run privileged instructions; user mode cannot, which protects the system.

    Q19. Which scheduling approach would you choose in each case: an interactive desktop, a batch job server, a real-time controller?

    Answer. Interactive desktop: multilevel feedback queue or round robin with a short quantum, for fast response and fairness to short tasks. Batch jobs: shortest-job-first style or priority scheduling, to maximize throughput and minimize average turnaround, with aging to avoid starvation. Real-time controller: a policy with guarantees such as earliest deadline first (run the task whose deadline is soonest; optimal on one CPU if the load is feasible) or rate-monotonic priorities (shorter period gets higher priority).

    Q20. What is the difference between a zombie and an orphan process? What is virtualization and how do containers differ from virtual machines?

    Answer. A zombie has finished but its parent has not yet collected its exit status, so its PCB entry remains. An orphan is a running process whose parent has exited; it is adopted by init. A virtual machine uses a hypervisor to emulate whole hardware, each VM running its own operating system kernel; containers share the host kernel and isolate processes with namespaces (what they can see) and cgroups (what they can use), so they start faster and use less memory but give weaker isolation.

    Q21. What does disk scheduling do? Compare FCFS, SSTF and SCAN.

    Answer. It orders pending disk requests to reduce head movement, the main cost on rotating disks. See disk scheduling.

    Example: head at track 53, requests for 98, 183, 37, 122, 14, 124, 65, 67. FCFS total movement is 640 tracks. SSTF (nearest next) is 236. SCAN moving upward first reaches the end and returns. SSD drives have no seek time, so these matter less, but IO\frac{I}{O}OI​ scheduling still reduces write amplification and improves fairness.

    1.3 Computer architecture

    Concept primer

    Computer architecture questions test whether you can reason about performance. The unifying idea is that a machine is fast when it keeps its parts busy and keeps data close.

    Performance equation. CPU time = instruction count x cycles per instruction (CPI) x clock period. Improving one factor often hurts another; for example, a simpler instruction set may raise the instruction count but lower CPI and clock period. Amdahl's law bounds the benefit of speeding up a part: if a fraction fff of the time is improved by a factor s, overall speedup = 1(1−f)+fs\frac{1}{(1 - f) + \frac{f}{s}}(1−f)+sf​1​.

    Pipelining. Split an instruction into stages (fetch, decode, execute, memory, write back) and overlap instructions so that, ideally, one instruction finishes every cycle. Hazards break the ideal: structural (two instructions need one resource), data (an instruction needs a result not yet computed; fixed by forwarding or by stalling) and control (a branch changes the next instruction; fixed by prediction). Real CPI = 1 + average stall cycles per instruction.

    Caches and the memory hierarchy. Registers, L1, L2, L3, main memory and disk trade capacity for speed. Locality makes this work: temporal locality (recently used data is used again) and spatial locality (nearby data is used next). Average memory access time = hit time + miss rate x miss penalty. A cache is organized into blocks; direct-mapped places each block in exactly one slot, set-associative in any of k slots of a set, fully associative anywhere. Misses are compulsory (first touch), capacity (cache too small) or conflict (too many blocks mapping to one set). Write-through updates memory on every write; write-back updates memory only when a dirty block is evicted.

    Number representation. Two's complement stores a negative number as the bit pattern that adds to zero with its positive; an n-bit word covers −2n−1-2^{n-1}−2n−1 to 2n−1−12^{n-1} - 12n−1−1. Floating point (IEEE 754) stores a sign, an exponent and a fraction, so numbers have relative, not absolute, precision, and addition is not associative.

    Parallelism. Instruction-level parallelism (superscalar, out-of-order execution), data-level parallelism (SIMD, GPUs), thread-level parallelism (multicore). Cache coherence protocols keep copies consistent across cores; false sharing wastes time when unrelated variables share a cache line.

    Q1. What is the difference between RISC and CISC?

    Answer. RISC (reduced instruction set computer, such as ARM and RISC-V) has a small set of simple, fixed-length instructions, most of which take one cycle, with only load and store instructions touching memory and many registers; this makes pipelining easy and hardware simple. CISC (complex instruction set computer, such as x86) has many instructions of varying length, some doing a lot (for example, a string copy or a memory-to-memory add), which gives compact code but harder decoding. Modern x86 chips decode CISC instructions into RISC-like internal micro-operations, so the difference is mostly at the instruction-set level.

    Q2. Explain the addressing modes.

    Answer. An addressing mode says how an instruction finds its operand. Immediate: the value is in the instruction (add r1, 5). Register: operand is in a register. Direct (absolute): the instruction holds the memory address. Register indirect: a register holds the address (like a pointer). Indexed or base plus displacement: address = register + constant (array element or struct field). PC-relative: address = program counter + offset (branches and position-independent code). Auto-increment or decrement: the register is updated after or before use (stack and array walks).

    Q3. What are spatial and temporal locality, and why do caches work?

    Answer. Temporal locality: an item used recently is likely to be used again soon (a loop counter). Spatial locality: items near a recently used item are likely to be used soon (walking through an array). Caches keep recently used blocks (temporal) and fetch a whole block of neighbouring bytes at once (spatial), so most accesses hit a small fast memory instead of slow main memory.

    Example: summing a 2-D array row by row in C is fast because rows are contiguous; summing column by column jumps by a whole row each step and misses far more.

    Q4. A direct-mapped cache is 32 KB with 64-byte blocks, and addresses are 32 bits. How many bits are the offset, index and tag?

    The problem: the address is split into three parts. The offset selects the byte inside a block, the index selects which cache line to look in, and the tag is stored with the line and compared to confirm it holds the right memory block.

    Answer. 64 bytes = 262^{6}26, so the offset is 6 bits. 32 KB / 64B=51264 B = 51264B=512 lines = 292^{9}29, so the index is 9 bits. The tag is the rest: 32−9−6=1732 - 9 - 6 = 1732−9−6=17 bits. For a 4-way set-associative cache of the same size there are 128 sets, so the index is 7 bits and the tag is 19 bits.

    Q5. Compare direct-mapped, set-associative and fully associative caches. What are the three kinds of cache miss?

    Answer. Direct-mapped: each memory block can go in exactly one line; fast and simple, but blocks that map to the same line keep evicting each other (conflict misses). Fully associative: a block can go in any line; no conflict misses but needs a comparison against every tag, so it is slow and costly. Set-associative (n-way): a block maps to one set and can sit in any of the n lines in it; a compromise used in practice. Misses: compulsory (the first access to a block), capacity (the cache is too small for the working set), conflict (too many blocks map to the same set).

    Q6. What is average memory access time (AMAT)? Compute it for a two-level cache.

    Answer. AMAT = hit time + miss rate x miss penalty. For two levels: AMAT = L1 hit time + L1 miss rate x (L2 hit time + L2 local miss rate x memory time).

    Example: L1 hit 1 ns, L1 miss rate 5%, L2 hit 10 ns, L2 local miss rate 20%, memory 100 ns: AMAT = 1+0.05×(10+0.2×100)=1+0.05×30=2.51 + 0.05 \times (10 + 0.2 \times 100) = 1 + 0.05 \times 30 = 2.51+0.05×(10+0.2×100)=1+0.05×30=2.5 ns.

    Q7. Write-through versus write-back caches.

    Answer. Write-through writes to the cache and to memory on every store, keeping memory current but generating a lot of memory traffic (usually hidden by a write buffer). Write-back writes only to the cache and marks the line dirty; memory is updated when the line is evicted, which reduces traffic but makes cache coherence and crash consistency harder. On a write miss, write-allocate loads the block first (usually paired with write-back); no-write-allocate writes directly to memory (usually paired with write-through).

    Q8. What is cache coherence and why is it a problem on multicore chips?

    The problem: each core has its own cache. If core 1 writes variable x in its cache, core 2 may still hold an old copy of x, and so read a stale value.

    Answer. Cache coherence protocols keep all copies consistent. In a snooping protocol such as MESI, each line is in one of four states: Modified (this cache has the only up-to-date copy, memory is stale), Exclusive (the only copy, equal to memory), Shared (possibly several copies, all equal to memory), Invalid. A core must gain exclusive ownership before writing, which invalidates other copies. A practical consequence is false sharing: two unrelated variables that sit in the same cache line, written by different threads, make the line bounce between caches and slow the program; fix by padding or aligning data so hot variables sit on separate lines.

    Q9. Can you force a variable to live in the L2 cache in C++?

    Answer. Not directly: caches are managed by hardware, and the language gives no way to pin data to a particular level. You can influence it indirectly: keep the working set small enough to fit, access it in a cache-friendly order, use prefetch hints (for example, the compiler builtin __builtin_prefetch), and on some systems use cache partitioning features or non-temporal stores to avoid pollution.

    Q10. Explain the five-stage pipeline and its hazards.

    Answer. A pipeline overlaps the stages of consecutive instructions like an assembly line: fetch, decode, execute, memory access, write-back. Ideal speedup approaches the number of stages, with one instruction finishing per cycle. Hazards stop this: structural (two instructions need the same hardware; fix by duplicating resources), data (an instruction needs a result that is not ready yet; for example add r1, r2, r3 followed by sub r4, r1, r5; fixes: forwarding the result directly from the execute stage, or stalling when forwarding cannot help, as for a load followed immediately by a use), and control (the next instruction depends on a branch not yet resolved; fixes: branch prediction, with a 2-bit counter per branch, and flushing on a misprediction). CPI = 1 + average stall cycles per instruction.

    The problem: Amdahl's law says the serial part limits parallel speedup.

    Q13. How are integers and floating-point numbers represented? Why is 0.1 + 0.2 not exactly 0.3?

    Answer. Signed integers use two's complement: the top bit has weight −2n−1-2^{n-1}−2n−1, so negation is invert-and-add-one, and addition works the same for signed and unsigned. Floating point (IEEE 754) stores a sign, an exponent and a fraction, giving the value (−1)s×1(-1)^{s} \times 1(−1)s×1.f×2f \times 2f×2^(e - bias); double precision has 52 fraction bits (about 15 to 16 decimal digits). Many decimal fractions, including 0.1, have no finite binary representation, so they are stored rounded; the sum of the rounded 0.1 and 0.2 differs from the rounded 0.3 by about 5.5e-17. Consequences: never test floats for equality (use a tolerance), summation order changes results (floating-point addition is not associative), and use compensated (Kahan) summation or integers for money. This matters in quantitative code.

    Q14. What does out-of-order and superscalar execution mean? What is speculative execution?

    Answer. A superscalar processor can start several instructions per cycle. Out-of-order execution lets instructions run as soon as their operands are ready, rather than in program order, while committing results in order; register renaming removes false dependencies. Speculative execution runs instructions beyond an unresolved branch using a prediction, and discards the results if wrong; it improves speed but can leave traces in caches that attackers read (Spectre-style vulnerabilities).

    Q15. Why do GPUs differ from CPUs, and when do you use them?

    Answer. A CPU has a few powerful cores optimized for low latency on one thread (deep caches, branch prediction). A GPU has thousands of simpler cores optimized for throughput: many threads run the same instruction on different data (SIMT), and memory latency is hidden by switching between threads. Use GPUs for regular, data-parallel work such as matrix multiplication, neural-network training and Monte Carlo simulation of independent paths.

    1.4 Computer networks

    Concept primer

    Networking is organized in layers; each layer uses the one below and hides it from the one above. A good answer names the layer and the problem it solves.

    Layers. Link (frames between neighbours: Ethernet, Wi-Fi), network (packets between hosts across networks: IP, routing), transport (process to process: TCP reliability, UDP speed), application (HTTP, DNS, SMTP). Each layer adds a header (encapsulation) on the way down and removes it on the way up.

    Addressing and routing. An IP address identifies an interface; a subnet mask or prefix (for example /24) tells which bits name the network. Routers forward a packet to the next hop by looking up the longest matching prefix in a forwarding table. Routing protocols build the tables: link-state (every router learns the whole map and runs Dijkstra) and distance-vector (routers exchange distance estimates with neighbours; the Bellman-Ford idea).

    TCP. TCP gives an ordered, reliable byte stream over an unreliable network. It uses a three-way handshake to open, sequence numbers and acknowledgements to detect loss, retransmission on timeout, a sliding window for flow control (the receiver says how much it can take) and congestion control (the sender slows down when the network is overloaded). Congestion control: slow start doubles the window each round trip until a threshold; congestion avoidance then adds one segment per round trip; on loss the window is cut (halved after three duplicate acknowledgements, reset to one after a timeout). Throughput of a connection with window W and round-trip time RTT is about W / RTT.

    Delay. Total delay = transmission (size / bandwidth) + propagation (distance / signal speed) + queueing + processing. People confuse bandwidth (bits per second) with latency (time); a long fast pipe has high bandwidth-delay product, which is how much data must be in flight to fill it.

    Application layer. DNS maps names to addresses through a hierarchy of servers and caches; HTTP is a request-response protocol over TCP (HTTP/2 multiplexes requests, HTTP/3 runs over QUIC on UDP); TLS encrypts a connection using certificates and a key exchange.

    Q1. What happens when you type a URL into a browser and press Enter?

    Answer. (1) The browser checks its cache for the page. (2) It resolves the host name to an IP address through DNS: ask the local resolver, which asks a root server, then the top-level domain server, then the domain's authoritative server, and caches the answer. (3) It opens a TCP connection to that IP address on port 443 with a three-way handshake. (4) For https it runs a TLS handshake: the server sends its certificate, the browser checks that it is valid and signed by a trusted authority, and both sides agree on session keys. (5) It sends an HTTP request. (6) Packets cross routers, each forwarding by the destination address; the local network uses ARP to find the next hop's hardware address.     Q2. What is the difference between TCP and UDP, and when would you choose each?

    Answer. TCP is connection-oriented and gives a reliable, ordered byte stream, using sequence numbers, acknowledgements, retransmission, flow control and congestion control. UDP just sends independent datagrams with no connection, no guarantee of delivery or order, and no congestion control, so it has lower latency and overhead. Use TCP for web pages, file transfer, email (correctness matters). Use UDP for DNS lookups, live video or voice, games and market-data feeds (late data is useless, so retransmitting is worse than losing it), or when you build your own reliability on top (QUIC does this).

    Q3. Explain the TCP three-way handshake. Why three messages?

    Answer. Client sends SYN with its initial sequence number x. Server replies SYN-ACK: its own initial number y and an acknowledgement x + 1. Client sends ACK y + 1, and may start sending data. Three messages are needed so both sides confirm that the other can both send and receive and agree on starting sequence numbers; two messages would not let the server know the client received its sequence number, and old duplicated SYNs could create false connections. Closing uses FIN and ACK in each direction (four messages, since each direction closes independently), and the side that closes first waits in TIME_WAIT to make sure the last ACK arrives.

    Q8. Layers and devices. Name the layers, what each does, and the difference between a hub, a switch and a router.

    Answer. Application (HTTP, DNS), transport (TCP, UDP: process to process), network (IP: host to host across networks, routing), link (Ethernet, Wi-Fi: node to node on one network, uses MAC addresses), physical (bits on a medium). Each layer wraps the data from the layer above with its own header (encapsulation). A hub repeats bits to all ports (one collision domain). A switch learns which MAC address sits behind which port and forwards frames only there. A router connects different networks and forwards packets by IP address using a routing table.

    Q9. What do ARP, DHCP and NAT do?

    Answer. ARP finds the hardware (MAC) address of a device on the same network given its IP address, by broadcasting a question and caching the answer. DHCP automatically gives a joining device an IP address, subnet mask, default gateway and DNS server. NAT lets many devices on a private network share one public IP address: the router rewrites source addresses and ports on the way out and keeps a table to map replies back; it works around IPv4 address shortage but breaks end-to-end addressing.

    Q10. Compare link-state and distance-vector routing, and explain count-to-infinity.

    Answer. Link-state routing floods each router's local link costs to everyone, then each router computes shortest paths with Dijkstra on the full map (OSPF); it converges fast but needs more memory and flooding. Distance-vector routing has each router tell only neighbours its distance to every destination and update by Bellman-Ford (RIP); it is simple but slow to react to bad news. Count-to-infinity: if the link to a network fails, two neighbours can keep telling each other they have a route through the other, and the distance rises by one each exchange. Split horizon (do not advertise a route back to where you learned it) and poison reverse (advertise it with infinite cost) reduce the problem.

    Q12. How does Ethernet share a wire, and why can't Wi-Fi do the same?

    Answer. Classic Ethernet uses CSMA/CD: listen first, send if idle, detect collisions while sending, and back off for a random time that grows exponentially after each collision (see CSMA/CD and backoff). Wi-Fi cannot reliably detect a collision while transmitting, and a hidden-terminal problem exists (two senders cannot hear each other but both reach the access point), so it uses CSMA/CA: wait a random backoff before sending, and use acknowledgements (optionally request-to-send and clear-to-send messages) to confirm success.

    Q13. How are errors detected?

    Answer. A parity bit detects any odd number of flipped bits. A checksum (as in IP and TCP) adds up the data in fixed-size words and sends the sum. A cyclic redundancy check (CRC) treats the data as a polynomial over binary arithmetic, divides by an agreed generator polynomial, and appends the remainder; it detects all burst errors shorter than the remainder length and is used in Ethernet. Error correction (Hamming codes) adds enough redundant bits that the position of a single error can be computed.

    Q14. What is the difference between HTTP/1.1, HTTP/2 and HTTP/3, and what does TLS do?

    Answer. HTTP/1.1 sends requests one at a time per connection, so browsers open many connections. HTTP/2 multiplexes many requests over one TCP connection and compresses headers, but a lost TCP packet stalls all streams (head-of-line blocking). HTTP/3 runs over QUIC, built on UDP, giving independent streams, faster connection setup and loss recovery handled per stream. TLS gives confidentiality, integrity and server authentication: the handshake uses public-key cryptography (certificates, key exchange such as Diffie-Hellman) to agree a symmetric key, which then encrypts the data.

    1.5 Databases

    Concept primer

    Database questions are about modelling data correctly and keeping it correct when many users change it at once.

    Relational model. Data is stored in tables (relations) with rows (tuples) and columns (attributes). A key uniquely identifies a row; a primary key is the chosen key; a foreign key refers to a key in another table and enforces referential integrity. Relational algebra operations are select (filter rows), project (choose columns), join (combine rows of two tables on a condition), union and difference. SQL expresses these: SELECT columns FROM tables WHERE condition GROUP BY columns HAVING condition ORDER BY columns. WHERE filters rows before grouping; HAVING filters groups after aggregation. Joins: inner (matching pairs only) and left, right or full outer (keep unmatched rows with nulls).

    Design and normalization. A functional dependency X -> Y says that rows with equal X values have equal Y values. Bad design causes anomalies (updating a fact in one place but not another). Normal forms remove them: first normal form (atomic values), second (no partial dependence on part of a key), third (no dependence of a non-key on another non-key), Boyce-Codd (every determinant is a key). To test, compute attribute closures: the closure of X is everything functionally determined by X; X is a key if its closure is all attributes.

    Transactions and ACID. A transaction is a group of operations treated as one unit: atomicity (all or nothing), consistency (constraints hold before and after), isolation (concurrent transactions behave as if run one by one), durability (committed changes survive crashes, using a write-ahead log⁡\log log). Concurrency control: a schedule is serializable if equivalent to some serial order; two-phase locking (acquire all locks, then release) guarantees it but can deadlock. Isolation levels (read uncommitted, read committed, repeatable read, serializable) trade anomalies (dirty read, non-repeatable read, phantom) for speed.

    Storage and indexes. Data lives in disk pages. An index (usually a B+ tree) lets you find rows without scanning: a tree of height 3 or 4 covers millions of rows because each node holds hundreds of keys. Range queries scan the linked leaves. Hash indexes give fast equality lookup only. The query optimizer chooses join order and algorithm (nested loop, hash join, sort-merge join) by estimating costs.

    This section covers the database fundamentals every computer scientist should know: modelling, SQL, transactions and indexing.

    Q1. What do the letters in ACID mean? Illustrate with a bank transfer.

    The problem: a transaction moves 100 from account A to account B; it is two writes (debit A, credit B) that must behave as one unit.

    Answer. Atomicity: both writes happen or neither does (if the system crashes after the debit, the debit is undone); enforced with a log⁡\log log. Consistency: the transaction takes the database from one valid state to another (the total money is unchanged, no negative balances if that is a rule). Isolation: concurrent transactions behave as if they ran one at a time (another transaction never sees money missing from A but not yet in B); enforced by locking or versioning. Durability: once committed, the result survives crashes; enforced by writing a log⁡\log log to stable storage before reporting success (write-ahead logging).

    Q2. Normalization. A table R(A, B, C, D) has dependencies A to B and B to C (read: knowing A determines B, and knowing B determines C). Find a key, say which normal form R is in, and decompose to BCNF.

    The problem: a functional dependency X to Y means two rows that agree on X must agree on Y. Redundancy comes from dependencies whose left side is not a key. See attribute closure and BCNF decomposition for the steps.

    Answer. Closure of {A, D}: start with A, D; A gives B; B gives C; so the closure is {A, B, C, D}, the whole table, so AD is a key (and the only candidate key, since D is in no right-hand side). A to B has a left side A that is part of the key, a partial dependency, so R is only in 1NF, not 2NF. BCNF decomposition: A to B violates BCNF (A is not a superkey, since A's closure {A, B, C} lacks D); split into R1(A, B, C) and R2(A, D). In R1, B to C violates BCNF (B's closure is {B, C}, not all of R1); split into (B, C) and (A, B). Final tables: (B, C), (A, B), (A, D). The decomposition is lossless (joining recovers R) and keeps both dependencies.

    Q3. Write SQL for these. The table is Employee(id, name, dept, salary). (a) The second highest salary overall. (b) Employees earning more than the average of their department. (c) Departments with more than 5 employees. (d) The top earner in each department.

    Q4. Name the isolation anomalies and which isolation levels prevent them.

    The problem: concurrent transactions can see each other's partial work in several ways. A dirty read reads data another transaction has not committed. A non-repeatable read gets different values when reading the same row twice because another transaction committed a change in between. A phantom read gets different sets of rows when running the same range query twice because another transaction inserted rows.

    Answer. Read uncommitted allows all three. Read committed prevents dirty reads. Repeatable read also prevents non-repeatable reads. Serializable also prevents phantoms and makes the outcome equal to some serial order. Higher isolation costs concurrency. A lost update (two transactions read the same value, both add 10, the second write overwrites the first) is prevented by locking reads, by serializable isolation, or by optimistic version checks.

    Q5. Is this schedule conflict-serializable? Transactions T1 and T2 share item A: r1(A), r2(A), w1(A), w2(A) in that order (r is read, w is write).

    The problem: two operations conflict if they touch the same item, belong to different transactions, and at least one is a write. A schedule is conflict-serializable if it can be reordered into a serial schedule by swapping only non-conflicting operations; the precedence-graph test (see two-phase locking and the serializability test) decides this.

    Answer. Conflicts: r1(A) comes before w2(A), giving an edge T1 to T2; r2(A) comes before w1(A), giving an edge T2 to T1. The graph has a cycle, so the schedule is not serializable. It is the classic lost update: both read the old A, and the later write overwrites the earlier one.

    Q6. How does an index speed up queries? Compare a B+ tree and a hash index.

    Answer. Without an index, a lookup scans every row (O(n)). A B+ tree keeps keys sorted in wide nodes (one node per disk page, holding hundreds of keys), so a lookup reads only a few pages: with fan-out 100, a billion keys need about log⁡\log log base 100 of 109=4.510^{9} = 4.5109=4.5, so 5 levels. It supports equality, range queries (follow linked leaves) and ordering. A hash index gives O(1) average equality lookup but no range or order queries. Costs of an index: extra space and slower writes, since every insert must update it. Index the columns used in selective WHERE, JOIN and ORDER BY clauses.

    Q7. Compare join algorithms.

    Answer. To join tables R and S on a key: nested-loop join compares every pair, OOO(|R| x |S|), fine only with a tiny table or an index on the inner table (index nested loop). Hash join builds a hash table on the smaller table and probes it with each row of the other, OOO(|R| + |S|) when the hash table fits in memory. Sort-merge join sorts both on the key and merges them, O(nlog⁡n)O(n \log n)O(nlogn) and efficient if inputs are already sorted or the result must be sorted.

    Q8. What is write-ahead logging and how does recovery work after a crash?

    Answer. Before changing a data page on disk, the system appends a log⁡\log log record describing the change to the log⁡\log log and forces the log⁡\log log to stable storage; commit is complete when the commit record is on disk. After a crash, recovery reads the log⁡\log log: redo the changes of committed transactions that may not have reached the data pages, and undo the changes of transactions that did not commit. This gives atomicity and durability without writing every data page at commit.

    Q9. Row stores versus column stores; OLTP versus OLAP.

    Answer. OLTP workloads are many small transactions touching a few rows (orders, payments), best served by row stores. OLAP workloads scan huge numbers of rows but only a few columns (average price per day over years), best served by column stores, which keep each column together, compress very well and read only the needed columns. Market-data and time-series databases are usually columnar and partitioned by time.

    Q10. What does the CAP theorem say?

    Answer. A distributed data store cannot guarantee all three of consistency (every read sees the latest write), availability (every request gets a non-error answer) and partition tolerance (it keeps working when the network splits). Since partitions happen, during a partition you must choose between consistency (refuse some requests) and availability (answer with possibly stale data). Many systems pick per operation, and 'eventual consistency' is the common availability-leaning choice.

    1.6 Discrete mathematics and theory of computation

    Concept primer

    This section is the mathematical backbone for algorithm analysis and for knowing what computers cannot do. Expect short proofs.

    Proof techniques. Direct proof, contradiction (assume the opposite and derive an impossibility), contrapositive (to prove P implies Q, prove not Q implies not P), induction (prove the base case, then show that truth for n gives truth for n + 1; strong induction assumes all smaller cases), and the pigeonhole principle (more objects than boxes forces a box with two). Counting arguments and invariants are the next most common tools.

    Counting. Permutations of nnn distinct objects: nnn!. Choosing kkk of nnn: C(n,k)=nC(n, k) = nC(n,k)=n! / (kkk! (nnn - kkk)!). With repetition allowed: multiply choices.     Graph theory. The sum of all degrees is twice the number of edges, so the number of odd-degree vertices is even. A tree on n vertices has n - 1 edges and a unique path between any two vertices.     Number theory.     Theory of computation. A finite automaton recognizes regular languages (described by regular expressions); it has no memory beyond its current state, so it cannot count unboundedly (the pumping lemma proves a language such as anbna^{n} b^{n}anbn is not regular). A pushdown automaton adds a stack and recognizes context-free languages (programming-language syntax). A Turing machine models general computation. A problem is decidable if some Turing machine always halts with the right answer; the halting problem is undecidable (a diagonal argument). Complexity classes: P (solvable in polynomial time), NP (a proposed solution can be checked in polynomial time), NP-complete (hardest in NP: every NP problem reduces to it; SAT was the first, shown by Cook and Levin). To show a problem is NP-hard, reduce a known NP-hard problem to it in polynomial time.

    Q6. Design a finite automaton that accepts binary strings divisible by 3.

    Q7. Why is { anbna^{n} b^{n}anbn : n≥0n \ge 0n≥0 } not regular? What is the halting problem and why is it undecidable?

    Answer. Build a program D that on input a program Q runs H(Q, Q) and does the opposite: loops forever if H says Q halts on itself, halts if H says it loops. Then run D on its own description: if H says D(D) halts, D(D) loops; if H says it loops, D(D) halts. Either way H is wrong, a contradiction, so no such H exists. (This diagonal argument is the proof to know.)

    Q10. Define a vector subspace, a basis, and answer: are invertible matrices a subspace of all n by n matrices?

    Answer. A subspace of a vector space is a subset that contains the zero vector and is closed under addition and scalar multiplication. A basis is a set of linearly independent vectors that span the space; its size is the dimension. Invertible matrices are not a subspace: the zero matrix is not invertible, and the sum of two invertible matrices can be non-invertible (the identity plus minus the identity gives zero). The set of symmetric matrices, or of upper-triangular matrices, are subspaces. To solve a linear system with 10 to 20 unknowns, use Gaussian elimination with partial pivoting (O(n3))(O(n^{3}))(O(n3)), or an LU factorization when solving for several right-hand sides; for large sparse systems use iterative methods such as conjugate gradients.

    1.7 Programming, C++, Python and Linux

    Concept primer

    Programming questions check fluency, not trivia. Be ready to write correct code on paper and explain what happens in memory.

    C and C++. Memory has a stack (local variables, freed automatically on return), a heap (dynamic allocation, freed by you with free or delete, or by smart pointers) and static storage. A pointer holds an address; an array name decays to a pointer to its first element; pointer arithmetic scales by the element size. Typical bugs: dangling pointer (using memory after freeing it), memory leak, buffer overflow, uninitialized variable, double free. C++ adds classes, constructors and destructors (RAII: tie a resource's lifetime to an object's), references, templates, the standard containers (vector, map, unordered_map, set) and smart pointers (unique_ptr: single owner; shared_ptr: reference counted). Virtual functions enable runtime polymorphism through a table of function pointers (vtable). Know the difference between pass by value, by pointer and by reference, and between copy and move.

    Python. Everything is an object; variables are names bound to objects. Lists are dynamic arrays, dicts are hash tables, sets are hash sets; tuples and strings are immutable. Mutable default arguments are shared between calls, a classic trap. Generators produce values lazily. The global interpreter lock lets only one thread run Python bytecode at a time, so CPU-bound parallelism uses processes (or libraries such as NumPy that release the lock). Complexity of common operations matters: list append O(1) amortized, list insert at front O(n), dict lookup O(1) expected, "in" on a list O(n) but on a set O(1).

    Linux and shell. Everything is a file; processes have file descriptors 0, 1, 2 for input, output, error. Pipes connect the output of one command to the input of the next (grep, sort, uniq, awk, sed, cut, wc, find). Know permissions (rwx for owner, group, others, shown as octal such as 755), how fork creates a copy of a process and exec replaces its program, and how to inspect a running system (ps, top, df, du, lsof, strace).

    Writing code under time pressure. Restate the problem, give a tiny example, say your approach and its complexity before writing, handle edge cases (empty input, one element, duplicates, overflow), and test your code by tracing the example.

    Practical fluency matters as much as theory: know the languages and tools you use well enough to explain what happens in memory and at the command line.

    Q1. What is a function pointer? Write a snippet.

    Answer. A function pointer stores the address of a function so it can be called later or passed to other functions (callbacks, plug-in behaviour, sorting with a custom comparison). In C:

    int add(int a, int b) { return a + b; }
int apply(int (*f)(int, int), int x, int y) { return f(x, y); }
int (*p)(int, int) = add;   // declare and initialise
int r = apply(p, 2, 3);     // r == 5

    The declaration reads: p is a pointer to a function taking two ints and returning an int. Follow-up: in C++ prefer std::function or lambdas for flexibility; function pointers cannot hold state.

    Q2. What is the scope resolution operator in C++, and what problems can it cause?

    Answer. The operator :: selects a name from a specific scope: std::cout (namespace), Base::show() (a class's member), ::count (the global variable when a local one hides it). It resolves ambiguity, for example when two base classes have a member with the same name, or when a derived class wants to call the base version of an overridden function (Base::f()). Problems: forgetting it can make a local name hide a global; writing using namespace std in headers pollutes every file that includes them and can cause name clashes.

    Q3. What is the diamond problem? Why does C++ allow it and Java not?

    The problem: class B and class C both inherit from A, and class D inherits from both B and C. Then D contains two copies of A's members, and a call to an A member through D is ambiguous.

    Answer. C++ fixes it with virtual inheritance (class B : virtual public A, and the same for C), so D has only one shared A sub-object. C++ allows multiple inheritance of classes because its design goal is flexibility and zero-overhead abstraction, leaving the programmer to manage the complexity. Java disallows multiple inheritance of classes to keep the language simple and avoid the ambiguity; a class may implement multiple interfaces, and where two interfaces supply the same default method, the compiler requires the class to override it explicitly.

    Q4. Pointers, references, the stack and the heap; what are memory leaks and RAII?

    Answer. Stack memory holds local variables and function call frames; it is allocated and freed automatically in last-in first-out order and is fast but limited in size (deep recursion overflows it). Heap memory is allocated explicitly (new, malloc) and lives until freed; it is flexible but slower, and can fragment. A memory leak is heap memory never freed after it is no longer needed; a dangling pointer points to memory already freed; a segmentation fault is an access to memory the process may not touch (for example dereferencing a null or dangling pointer). A reference is another name for an existing object (cannot be null or reseated); a pointer holds an address and can be null and reassigned. RAII (resource acquisition is initialization) ties a resource's lifetime to an object's: the constructor acquires it and the destructor releases it, so cleanup happens even when exceptions occur; smart pointers such as unique_ptr and shared_ptr apply this to heap memory.

    Q5. Linux commands. (a) How do you check how much disk space each user's home directory uses? (b) How do you see memory use by process? (c) What does the watch command do?

    Answer. (a) du -sh /home/* prints the total size of each directory under /home in human-readable units (-s summarizes each argument instead of listing every file, -h prints K, M, G); sort with | sort -h. df -h shows free space per mounted disk. (b) free -h shows total, used and free memory; ps aux --sort=-%mem | head lists the processes using the most memory; top or htop shows live usage. (c) watch -n 2 'command' runs the command repeatedly every 2 seconds and shows its output full screen, highlighting changes with the -d flag; useful for monitoring, for example watch -n 1 'free -h' or watch -d 'ls -l'. Other basics worth knowing: grep -r for searching text, find for files, chmod and chown for permissions, ssh and scp, tail -f for following logs, kill and kill -9, crontab for scheduled jobs.

    Q6. Python: what is the GIL; list versus tuple; generators; mutable default arguments?

    Answer. The global interpreter lock (GIL) in standard CPython lets only one thread run Python bytecode at a time, so threads do not speed up CPU-bound code (use multiprocessing, native extensions or NumPy for that), but they still help with IO\frac{I}{O}OI​-bound work. Lists are mutable, tuples are immutable (and hashable if their contents are, so usable as dictionary keys). A generator produces values lazily with yield, using constant memory, for example iterating over a huge file. The mutable default argument trap: def f(x, items=[]) creates the list once when the function is defined, so it is shared across calls; use items=None and create a new list inside. Copying: assignment shares the object; copy.copy makes a shallow copy; copy.deepcopy copies nested objects too. Costs: list append OOO(1) amortized, dict and set lookup OOO(1) average, sorted() O(nlog⁡n)O(n \log n)O(nlogn), heapq push and pop O(log⁡n)O(\log n)O(logn).

    Q7. Code it on paper. (a) Check whether a string of brackets such as '([]{})' is balanced. (b) Reverse the words in a sentence. (c) Find the first non-repeating character in a string.

    Answer. (a) Scan left to right with a stack: push each opening bracket; for a closing bracket, the stack must be non-empty and its top must be the matching opener, which you pop; at the end the stack must be empty. O(n). (b) Split on spaces, reverse the list, join with spaces; in place in C, reverse the whole string, then reverse each word. O(n). (c) Count occurrences with a hash map in one pass, then scan again for the first character with count 1. O(n) time and O(alphabet size) space. Write code neatly, name variables clearly, state complexity, and test with an empty string and a one-character string.

    Q8. How would you test a function you wrote, and what do you do when a bug reaches production?

    Answer. Test normal cases, boundary cases (empty, one element, maximum size, duplicates), invalid inputs, and compare against a trusted slow version on random inputs (randomized differential testing). Add regression tests for each bug found. For a shipped bug, give an honest story: what went wrong, how you found it, how you fixed it, and what you changed (a test, a code-review check, a monitoring alert) so it would not happen again.

    Q9. Git in one minute.

    Answer. Git stores snapshots of a project as commits in a graph; a branch is a movable pointer to a commit. Merge combines two branches and records a merge commit, preserving history; rebase replays your commits on top of another branch for a linear history (do not rebase commits that others have already pulled). Useful commands: git status, git diff, git add, git commit, git log⁡\log log --oneline, git branch, git checkout or switch, git pull, git push, git stash.
